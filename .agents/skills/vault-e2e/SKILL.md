# Vault E2E

## 먼저 실행할 테스트를 묻는다

스킬을 호출하면 서버 조회나 테스트 실행보다 먼저 다음 질문을 한다. 이 질문에 답을 받은 뒤 선택한 범위만 실행한다. 사용자가 같은 호출에서 이미 하나를 명확히 선택했다면 다시 묻지 않는다. 스킬 작성·수정 요청 자체는 테스트 실행 요청이 아니다.

> 어떤 테스트를 실행할까요?
>
> 1. 주력 suite — Vault/API 동작, 브라우저·Google 로그인 불필요
> 2. Web E2E — Web 전체 여정
> 3. 둘 다 — 주력 suite 다음 Web E2E

`request_user_input_async`가 있으면 위 세 선택지를 제시하고 답을 기다린다. 없으면 일반 응답으로 질문한다. 답이 오기 전 서버를 띄우거나 테스트를 시작하지 않는다.

| 선택 | 루트에서 실행할 명령 |
| --- | --- |
| 주력 suite | `pnpm test:vault:suite` |
| Web E2E | `pnpm test:vault:app` |
| 둘 다 | `pnpm test:vault:all` |

선택 후 [시행착오와 해결 기록](references/lessons.md)의 해당 범위를 읽고 같은 실수를 반복하지 않게 준비한다.

## 주력 suite

[suite 안내](../../../docs/devs/vault-e2e-suite.md)의 주력 테스트 범위와 실행기 정리 규칙을 읽는다. 현재 브랜치·작업 트리의 변경을 보존하고 선택한 명령을 실행한다. 실행기가 임시 PostgreSQL·객체 저장소를 준비한다. 기존 개발 DB나 `.env`의 DB를 테스트 대상으로 채택하지 않는다.

주력 suite만 선택했으면 브라우저 로그인 준비를 요구하지 않는다. `all`의 주력 실패는 앱 실행을 생략하지 않지만, 사용자 중단은 다음 실행을 중단한다.

## 실패는 수정과 재검증까지 완료한다

선택한 범위의 실행 요청은 실패 원인 진단, 필요한 제품·실행기·기존 테스트·흐름 수정, 같은 범위의 재실행까지 포함한다. 실패 보고서와 원인을 확인한 뒤 해결 가능한 문제는 추가 승인 없이 수정하고, 새 격리 환경에서 선택 범위 전체가 통과할 때까지 진행한다. 첫 실패 결과만 보고하고 작업을 끝내지 않는다.

- 계약과 실제 호출·저장 결과를 비교해 제품 실패, 검증 누락, 환경 실패를 구분한다. coverage 누락은 기존 테스트에 실제 동작과 결과 검증을 보완한다. 기대값 축소, 검증 삭제, skip 또는 실패·미실행의 성공 처리를 해결로 삼지 않는다.
- 변경 후 기존 실패 증거를 보존하고 새 보고서로 해결 여부를 확인한다. Web qualification의 두 번 새 환경·동일 소스 조건은 유지한다. 최종 diff와 영향을 받는 호출자를 검토하고, 실제 통과한 범위만 완료로 보고한다.
- 사용자 중단 또는 추가 인증·외부 서비스·기기 등 사용자가 해결해야 하는 구체적인 조건에서만 종속 실행을 기다린다. 그 조건과 완료한 범위·남은 검증을 명시하며, 독립적으로 가능한 수정은 계속한다. 선택 범위와 아래 승인 제외 사항을 유지한다.

## Web E2E

실행 전에 [앱 환경 가이드](references/app-environment.md)를 읽고 서버·OAuth·Chromium 준비를 끝낸다. 세부 계약은 [앱 계획](../../../docs/devs/vault-app-e2e-plan.md), 현재 구현 상태는 실행기와 `.argent/flows/vault/journey-manifest.json`에서 확인한다. 오래된 기록의 성공 수치나 서버 상태를 현재 사실로 사용하지 않는다.

- UI·런타임 작업에는 해당 Argent 스킬을 먼저 읽는다. 녹화·수정은 `argent-qa-flows`와 `argent-create-flow`, Chromium 조작은 `argent-device-interact`를 사용한다.
- 전체 실행마다 새 일반 계정 하나와 전용 DB 하나를 쓴다. 같은 실행의 모든 Web 기능은 동일 일반 계정을 유지한다. 관리자는 별도 계정이다.
- Web 무료 Memo → Admin Google 라이선스 발급 → 일반 계정 등록 → Quest 이용권 등록·시작 → Market 전체 구매 → 유료 Diary → 셔플 저장·재진입 → 전체 소유권 → 장식 30개 적용 → Quest 보상 10단계의 10개 stage를 검증한다. 모바일 테스트 및 이미지 업로드·스토어/RevenueCat 구매·복원은 제외한다. 사진 picker/fixture나 Computer Use를 준비하지 않는다.
- 실제 관리자 Google OAuth를 유료 여정의 선행 조건으로 먼저 확인한다. 기존 통과 흐름을 재사용해 전체 여정을 연결하고, 변경·실패·새 의심이 없는 개별 흐름을 반복 검증하지 않는다.
- 자동 qualification은 변경 없는 전체 여정 두 번을 각각 새 환경에서 검증한다. version 3 manifest에서 Chromium의 10단계를 모두 요구한다. 누락된 manifest·흐름을 성공 처리하지 않는다. 녹화 모드나 일부 단계 재생은 전체 앱 통과가 아니다.

## 결과와 중단

사용자의 최신 판정 기준(2026-10-02)에 따라 Argent의 passing idle에 붙는 정확한 localized pixel-change 경고는 별도 진단으로 보고한다. 목적지·UI acceptance·canonical 저장 검증은 모두 성공해야 한다. 화면 트리 부족, 캡처 증거 부재, 다른/알 수 없는 경고, 실제 실패·skip·미실행은 차단한다. 이 기준은 Argent QA 스킬의 모든 passing warning을 차단하는 기본값보다 우선하는 사용자 지시다. 이전 strict 실행 기록의 code 2를 소급 변경하지 않는다.

실행 명령, 종료 코드, 실제 보고서 경로, 완료·실패·미실행 단계와 정확한 장애를 보고한다. 0은 전체 선택 범위 통과, 1은 확인된 테스트/제품 실패, 2는 환경·미실행·증거 부족, 130은 중단이다. API suite 통과와 앱 전체 통과를 구분하고, 측정하지 않은 완성도 비율을 제시하지 않는다.

이번 실행이 소유한 서버·DB·프로필·secret lease만 정리한다. 사용자가 연 서버는 보존한다. 저장된 보고서와 실패 증거는 유지한다. 추가 인증 등 사용자가 해결해야 하는 조건에서는 그 조건을 구체적으로 요청하고 종속 실행을 기다린다.

이 스킬은 repo-wide fix/typecheck, 새 테스트 파일, 운영 DB 변경, 배포나 RevenueCat 테스트를 승인하지 않는다.

## 시행착오를 계속 갱신한다

사용자는 이후 테스트에서 확인한 시행착오도 이 스킬에 계속 반영하도록 요청했다. 새로운 원인·해결 방법을 확인했거나 실행을 종료할 때 [해결 기록](references/lessons.md)을 갱신한다. 반복 로그 대신 다음 실행의 판단을 바꾸는 내용만 남긴다.

- 증상, 관측한 원인과 미확인 가설, 취한 조치, 검증 범위·보고서 경로, 다음 실행의 예방 조치를 기록한다. 미해결·구현만 완료·부분 검증·전체 검증을 구분한다.
- 같은 문제는 기존 항목을 갱신하고, 원인이나 상태가 달라진 근거를 남긴다. 자세한 실행 로그는 앱 계획/보고서를 연결한다. 과거 실패 증거는 보존한다.
- 반복 사용해야 할 환경 준비 방법은 `app-environment.md`, 공통 실행 판단은 이 파일에 반영한다. 같은 가이드를 여러 파일에 복제하지 않는다. 기록을 실제 읽는 경로로 연결한다.
- 해결 전 확인되지 않은 가설을 규칙으로 승격하지 않는다. 현재 프로세스 ID·포트·계정·성공 수치는 매번 확인하며 과거 값을 기본값으로 고정하지 않는다.
- 비밀번호·OAuth secret·라이선스 원문·민감한 사용자 데이터는 기록하지 않는다. 이 갱신은 프로젝트 스킬에만 적용하며 `AGENTS.md`나 별도 개인 메모리에는 쓰지 않는다.
