# 체크리스트 추가

`daily`, `idea`·`아이디어`, `backlog`·`백로그`, `bug`·`버그`에 내용을 추가할 때 읽는다. `daily <일> <번호>` 토글은 별도 참조를 따른다.

## 대상 문서

| 대상 | 파일 | 새 파일의 `title` / `description` | 인덱스 |
| --- | --- | --- | --- |
| `daily` | `work-log/YYYY-MM-DD.mdx` | 오늘 날짜 / 작업일지 | `work-log/meta.json` |
| `idea` | `idea.mdx` | 아이디어 / 나중에 해볼 아이디어 메모 | `meta.json` |
| `backlog` | `backlog.mdx` | 백로그 / 나중에 할 일 백로그 | `meta.json` |
| `bug` | `known-bugs.mdx` | 알려진 버그 / 확인된 버그 기록 | `meta.json` |

없는 문서는 표의 `title`과 `description`을 YAML frontmatter로 생성한다.

## 항목 형식

- 아이디어는 `- [ ] <내용>`; 작업일지·백로그·버그는 `- [ ] N. <내용>`이다.
- 새 상위 번호는 대상 파일의 마지막 상위 번호 + 1이며 첫 번호는 1이다. 사용자가 부모 `N`을 지정한 경우에만 그 부모 아래 다음 `N-M.` 번호를 쓴다. 기존 번호는 유지한다.
- 작업일지는 문구를 유지하며 아래 카테고리를 적용한다. 아이디어·백로그는 의도를 짧은 할일로, 버그는 증상과 조건으로 다시 쓴다. 내용을 보태지 않는다.
- 여러 항목은 각각 한 줄에 쓴다. 기존 체크리스트 마지막 줄 뒤에 추가하되, 자식 항목은 지정한 부모 아래에 둔다. 체크리스트가 없으면 frontmatter 다음 빈 줄 뒤에 쓴다. 섹션 헤딩과 비체크리스트 본문은 건드리지 않는다.
- 문구 정리와 카테고리 적용 후 같은 내용이 이미 있으면 추가하지 않고 알린다. 비교할 때 체크 상태와 항목 번호는 제외한다.

## 카테고리

카테고리가 분명하면 내용 앞에 `라벨 (이모지):`를 붙인다. 번호는 카테고리보다 앞에 온다: `- [ ] 1. 메모 (📝): 편집창 단축키 정리`.

| 라벨 | 이모지 | 해당 맥락 |
| --- | --- | --- |
| 리포 | 📦 | 모노레포·패키지 구조, `apps/`·`packages/` 정리 |
| 문서함 | 📚 | 어드민 문서함·개요·치트시트·docs 페이지 |
| 다이어리 | 📅 | 다이어리 화면·일정 UI |
| 캘린더 | 🗓️ | 캘린더 화면·월/주 뷰 |
| 메모 | 📝 | 메모 편집·편집창·섹션·블록 편집 |
| DB | 🗄️ | 스키마·마이그레이션·page table·컬럼·DB 테이블 |

이미 `라벨 (이모지):`가 있으면 그대로 둔다. 표의 명시 접두사(`메모:`, `DB:` 등)는 고정 이모지 형식으로 바꾸고 뒤 문구를 유지한다. 접두사가 없어도 맥락이 분명하면 붙이며 앞부분의 중복된 카테고리 수식은 한 번만 남긴다. 애매하거나 표 밖의 영역이면 라벨·이모지를 만들지 않는다.

## 인덱스와 완료

- 작업일지는 `work-log/meta.json`의 `pages` 맨 앞에 오늘 날짜를 중복 없이 둔다. `title`은 `오늘 작업일지`, `defaultOpen`은 `true`로 유지한다.
- 다른 대상은 루트 `meta.json`의 `pages`에 해당 slug가 없을 때만 `cheatsheet` 뒤에 넣고 기존 항목의 상대 순서는 유지한다.

추가한 줄과 필요한 인덱스 항목이 저장되면 완료다. 기존 항목의 문구·번호·체크 상태와 관련 없는 메타데이터가 보존됐는지 확인한다.
