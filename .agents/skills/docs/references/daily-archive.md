# 지난 작업일지 주간 보관

기본 대상은 `work-log/`의 오늘 이전 날짜 파일이다. 사용자가 보관 범위를 지정하면 그 범위를 따른다.

## 보관 형식

- `work-log-archive/YYYY-MM-wN.mdx`에 월요일~일요일 기준 주차별로 직접 보관한다. 기존 날짜→주차 배치를 유지한다(`2026-08-13` → `2026-08-w2`). 월별 폴더는 만들지 않는다.
- frontmatter는 `title: M월 N주차`, `description: 과거 작업일지`이다.
- 각 일지 본문을 `## YYYY-MM-DD` 아래에 보존하고 날짜 내림차순으로 배치한다. 항목 문구, 번호, 체크 상태와 비체크리스트 내용도 유지한다.

## 이동과 인덱스

1. 대상 원본과 해당 주차의 기존 보관 페이지를 읽고 날짜별 본문을 병합한다. 동일 날짜·동일 내용은 중복 생성하지 않는다. 동일 날짜의 내용이 다르면 덮어쓰거나 원본을 삭제하지 않고 충돌을 알린다.
2. 보관 페이지를 저장하고 다시 읽어 대상 날짜의 본문이 온전히 보존됐는지 확인한다. 확인된 날짜만 `work-log/`에서 삭제하고 `work-log/meta.json`의 `pages`에서 제거한다.
3. `work-log-archive/meta.json`은 `title: 과거 작업일지`, `defaultOpen: false`로 두고 `pages`에는 최신 주차 slug부터 중복 없이 등록한다.
4. 루트 `meta.json`의 `pages`에 `work-log-archive`가 없으면 `work-log` 뒤에 넣는다. 관련 없는 항목과 메타데이터는 유지한다.

요청 범위의 본문이 보관되고 원본·인덱스가 일치하면 완료다. 보관 페이지와 날짜 목록, 충돌 등으로 남긴 원본을 알린다.
