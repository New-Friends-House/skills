# 치트시트

호출 하나를 `cheatsheet/<slug>.mdx` 새 페이지 하나로 정리한다. 관련 명령이 여러 개여도 한 페이지에 두며 필요하면 `##` / `###`로 나눈다. 체크리스트 번호·카테고리 규칙은 적용하지 않는다.

## 내용 계약

- 제목과 설명은 사용자의 의도를 짧게 다시 쓴다. 제목은 주제를, 설명은 언제·왜 쓰는지를 전달한다.
- 사용자가 준 명령 문자열은 코드 펜스 안에 byte-for-byte 보존한다. 플래그·경로·환경변수를 추가하거나 추정하지 않는다. 문서에 기록하는 요청은 명령 실행을 허용하지 않는다.
- 명령만 주면 본문 설명은 생략하고, 설명만 주면 코드 펜스 없이 본문만 쓴다.

````mdx
---
title: <짧은 제목>
description: <한 줄 요약>
---

```bash
<사용자 제공 명령>
```

<필요한 경우 한 문장 설명>
````

## 파일과 인덱스

- 제목에 맞는 ASCII kebab-case slug를 쓴다. 동일 slug 파일이 있으면 덮어쓰거나 다른 이름으로 추가하지 않고 이미 있다고 알린다.
- `cheatsheet/meta.json`의 `pages` 끝에 slug를 추가하며 기존 순서를 유지한다. 인덱스가 없으면 `title: 치트시트`, `defaultOpen: true`, `pages: []`로 만든다.
- 루트 `meta.json`의 `pages`에 `cheatsheet`가 없으면 `toc` 뒤에 넣는다.

페이지와 인덱스가 저장되고 명령 문자열이 원문과 같으면 완료다. 새 페이지 경로와 제목을 알린다.
